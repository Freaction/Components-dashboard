# Архитектура высоконагруженных операций в Rust (Performance)

Этот документ описывает стандарты и паттерны написания высокопроизводительного кода на Rust для обработки миллионов записей из базы данных. Если перед вами стоит задача разработать новый эндпоинт поиска, парсинга или индексации, соблюдайте эти архитектурные правила.

## 1. Zero-Allocation First
При последовательном (однопоточном) чтении гигантских объемов данных из SQLite избегайте лишних выделений памяти в куче (`String`, `Vec`).
- Читайте данные "напрямую" по ссылке через `row.get_ref(0)`.
- Если это текст, парсите байты через `std::str::from_utf8(bytes)` без создания `String`.
- Это радикально снижает нагрузку на аллокатор памяти и экономит десятки секунд времени на миллионах строк.

## 2. Защита от Thundering Herd (Шторм запросов)
Ресурсоемкие операции (например, подсчет статистики или глобальный поиск) обычно кэшируются. Однако, когда кэш холодный, параллельные запросы от фронтенда могут вызвать старт одних и тех же тяжелых SQL-операций одновременно, парализуя БД.
- Обязательно используйте точечную блокировку по уникальным ключам (например, `tokio::sync::Mutex` внутри `std::collections::HashMap`, разбитый по `team_id`).
- Приходящие дублирующие запросы должны тихо "ждать" (await) на мьютексе, пока первый поток не завершит работу и не положит результат в общий кэш.

## 3. Архитектура Parallel Scanner (Map-Reduce)
Если бизнес-логика требует тяжелых CPU-вычислений (регулярные выражения, сложные поиски подстрок, десериализация огромных JSON), одного ядра может не хватить. В этом случае используется параллелизм на базе крейта `rayon` по модели Map-Reduce.

**Пошаговая инструкция для внедрения:**
1. **Единый узел обработки**: Создайте центральный модуль (например, `ParallelScanner`), который будет принимать SQL-запрос, размер чанка и функцию (closure) для обработки.
2. **Пакетное чтение (Chunking)**: Читайте данные из SQLite батчами (например, по `50 000` строк за раз). Здесь *придется* аллоцировать `String` (так как данные SQLite должны пережить отправку в другой поток). Соберите их в `Vec<String>`.
3. **Параллельная проекция (Map)**: Передайте собранный чанк крейту `rayon` (запустите `.par_iter()`). `rayon` мгновенно распределит строки по всем физическим ядрам процессора.
4. **Агрегация (Reduce)**: Слейте результаты из параллельных потоков воедино (например, объединив `HashMap`).
5. Переходите к следующему чанку SQLite, пока данные не закончатся.

*Этот паттерн обеспечивает баланс между использованием оперативной памяти (читаем только по 50k строк) и загрузкой процессора (100% утилизация всех ядер).*
